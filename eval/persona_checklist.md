# Persona checklist

Ten probes per persona, covering the six things product.md and the decision log actually
promise about how Sarjy speaks:

| covered | where it comes from | probes |
| --- | --- | --- |
| dialect purity — no Modern Standard Arabic drift | golden rule 9, D-032 | 1, 2 |
| no cross-dialect vocabulary | D-032 (the first Egyptian build greeted with "يا هلا") | 1, 8 |
| brevity and speakability | SPOKEN_STYLE_RULES — it is read aloud, never read | 3, 4 |
| the honesty clause | D-044 → D-061 | 5 |
| borrowed words in Arabic script | product.md §6.4 | 6 |
| language mirroring, and an explicit switch sticking | product.md §6.1, §6.2 | 7, 8, 9 |
| a prayer-anchored request end to end | product.md §8, D-054 | 10 |

Regenerate with `backend/venv/bin/python eval/persona_probe.py --write` against a running API.
It runs over `POST /api/chat`, so a full pass costs twenty brain turns and **no TTS quota**.

## How to read the two verdict columns

**lint** is mechanical and re-run every time: reply length, markdown, emoji, URLs, Modern
Standard Arabic tell-tales, the *other* persona's vocabulary, Latin script inside an Arabic
reply, which language was answered in, and which tools were called. A red cell here is a
prompt bug — the fix goes in `app/personas.py` and the probe is re-run.

**ear** is the builder's, and it is the half a linter cannot do: *does this sound like a person
from that place*. Egyptian is judged natively; Gulf against ten years in Saudi Arabia
(product.md §7). If the Gulf **voice** rather than the text sounds wrong, D-026's revisit
clause applies and the fix is the one-variable swap of D-024.

## What this found

Three things, on the first run:

1. **§6.2 was not working at all.** "كلمني عربي" followed immediately by an English question
   came back in English, on *both* personas. `preferred_language` was written only by the fact
   extractor (D-058) — a second model call that runs *after* the reply — so the preference
   arrived a turn late over the socket and never at all over `POST /api/chat`, which does not
   run the extractor. Fixed by recognising the request deterministically inside the turn
   (`language.explicit_language_request`, D-064). Both personas now pass 10/10.
2. **One reply appended an English sentence to an Arabic one** — "…عامل إيه؟ؤ Everything looks
   good." — which breaks "one language per reply". Not reproduced on three re-runs of the same
   probe, so it is recorded as an observed model glitch rather than patched for; the lint will
   catch it if it comes back.
3. Nothing else. No MSA drift, no cross-dialect vocabulary, no markdown, no Latin script in an
   Arabic reply, and every tool the probes expected was called.
